## 2026-10-27 (화)

오늘 commit 36건 (그중 Tesollo 핸드 27건). 사람: 목표·티칭·실기 실행·판정 / Claude: 설계·코드·디버깅·계획 / Codex: 슬롯 CNN 실험.

### 1. 다지 핸드 힘 제어 파지 도구 (제조사 SDK)
- 문제: 제조사 Python SDK로 힘 제어 파지(설정 힘까지 닫고 유지)를 하려는데 세 번 연속 막힘.
- AI 활용: 오류마다 Claude가 제조사 예제, 헤더 문서, 제조사 GUI(DGManager)의 내부 코드를 읽고 원인을 찾아 고침.
  사람은 실기 실행과 화면 캡처만.
- 결과 (원인 → 수정):
  1. 연결 즉시 강제 종료(segfault) → 연결 전에 콜백 등록이 필수 (제조사 예제 순서와 비교)
  2. 시작 명령 'NOT_FOUND_MODEL' → 설정 직후 0.1 s 대기가 필요 (0 s 2/2 실패, 0.1 s 2/2 성공 측정)
  3. 명령은 '정상'인데 손가락이 안 움직임(전류 0 mA) → 개발자 모드는 PC가 모터 게인을 보내야 함 (DGManager 코드에서 확인)
- 검증: 각 원인을 로봇 동작 없는 연결·읽기 시험으로 먼저 확인한 뒤 사람이 실기 실행.
- 재작업: 2번에서 처음엔 다른 원인(관절 수 설정)을 짚었다가 측정으로 정정 → "AI 진단도 측정으로 확인" 사례.

### 2. 파지 자세와 물체별 분기
- 문제: 접시·그릇을 어떤 손 모양과 힘으로 잡을지.
- AI 활용: 사람이 DGManager에서 손 자세를 티칭(pose 9, 20, 30)하면 Claude가 그 값을 읽어 코드로 저장.
  힘 상한은 제조사 매뉴얼에서 확인(0-20 N, 손가락 끝 최대 19.4 N).
- 결과: plate = pose 0 → 접근 → pose 9 → 5손가락 평행 파지 7 N / bowl = pose 30 → 5손가락 파지 7 N.
  YOLOE가 본 물체 종류로 자동 분기.
- 재작업: DGManager가 저장 전 종료되며 레시피 2개가 사라짐 → Claude가 미리 읽어 둔 값으로 복구하고 저장소에 별도 보관.

### 3. 인식 → 파지 경로 (카메라로 물체 위치 측정)
- 문제: 물체 위치가 바뀌어도 잡으러 가야 함.
- AI 활용: 기존 YOLOE·깊이 카메라·좌표 보정 코드를 재사용해 '물체 중심 위치' 측정 도구를 새로 만듦.
  가르친 위치와의 차이(dx, dy)만큼 로봇 자세를 평행이동.
- 결과: 사진 5장 사이 오차 0.8-4.4 mm. 테이블 위 다른 그릇·접시는 '잡는 자리에서 30 cm 안에서 가장 가까운 것'으로 걸러냄.
- 재작업: 첫 시험에서 1.5 m 떨어진 그릇을 집으려 함(신뢰도 순) → 거리 기준으로 고침. 빨간 접시 신뢰도가 낮아(0.17-0.26) 기준값 조정.

### 4. 바구니까지 운반·삽입 경로 (기존 그리퍼 코드 재사용)
- 문제: 그리퍼(2F-85)로 만든 바구니 넣기를 다지 핸드로 옮기기.
- AI 활용: 그리퍼용 바구니 경로 계획기를 그대로 쓰고, '손 안의 접시 위치'와 손 크기만 핸드에 맞게 바꿈.
  그릇은 세운 채 분면에 내려놓는 계획을 새로 만듦.
- 결과 (실기): **bowl → 바구니 Q3 성공** (보정 1회: +y 10 cm, 10 cm 더 낮게). plate: 파지·운반 성공, 삽입 위치 +y 5 cm 보정 반영.
- 재작업 (사람이 잡아낸 AI 실수, 발표의 '검증 루프' 근거):
  - 설정 파일의 RRT 경로를 써서 운반 경로가 이상함 → 그리퍼 기본(직선 상승-이동-하강)으로 교정
  - '놓기'가 '하강'보다 먼저 가능한 순서 오류 → 하강까지 한 번에, 하강 전 놓기는 재확인
  - 손목 특이점 근처에서 직선 경로가 손목을 100° 이상 뒤집음 → 관절 공간 경로 + 기울기·이탈 검사로 교체 (AI가 검사로 발견)
  - 경로 30분 만료로 두 번 거부 → 매번 새로 계획하는 실행 명령 추가
  - 속도 기본값이 너무 느림 → 기본 80°/s + 사람이 지정 가능하게

### 5. Codex: 슬롯 CNN 실사진 보강 실험

### 2. 사람과 AI의 실시간 협업으로 시연 시퀀스 완성 (하루, 실기 반복)
